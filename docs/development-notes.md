# 開発メモ

## 開発目的

山留め関連Dynamo一式を、Revit APIベースの専用アドインとして再構成する。

現行のOrkestraリボン実行運用を踏まえ、単純なDynamoファイル移植ではなく、利用者が通常のRevitコマンドとして扱いやすいUIと処理単位に整理する。

## 想定技術構成

- Revit 2023
- C#
- .NET Framework 4.8
- WPF
- Revit API

## 実装時の設計メモ

- リボンタブ名は暫定で「生産技術部」とし、後で変更しやすいように定数化する。
- 各コマンドはExternalCommandとして分離する。
- 共通処理はサービス化する。
- Excel読込は可能な範囲でClosedXMLまたはOpenXML SDKを検討する。
- 設定情報はRevitのDataStorageおよびExtensibleStorageでプロジェクト内に保存する方針を検討する。
- エラー表示はDynamo/Pythonの例外をそのまま見せず、業務向けメッセージに変換する。
- 実行前チェックにより、選択不足、設定不足、ファミリ不足、ビュー不足を事前に検知する。
